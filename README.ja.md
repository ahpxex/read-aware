## 一つのリーダー。一つのエージェント。開かれたプラグイン。

ReadAware は macOS、Windows、Linux、Android、iOS で使える無料のオープン
ソースリーダーです。その中心には一つのエージェントがいます。ツールを使い、
文脈に沿って質問に答え、あなたが大切にする本・一節・メモ・会話から育ちつづ
ける記憶を築きます。そのまわりを囲むのが、リーダーを——そしてエージェント
自身を——内側から拡張するサンドボックス化されたプラグインシステムです。

- **文とともに。** 一文ずつ読むスタイルが、ページを静かで集中しやすく、
  ADHD フレンドリーに保ちます。
- **自分のやり方でマークする。** 読書の流れを断ち切らずに、下線・ハイライト・
  メモが書けます。
- **ページから聞く。** わからない一節を AI と話す、気になる考えを掘り下げる、
  単語を調べる——どれも本から離れずにできます。
- **内側から拡張する。** 内蔵マーケットプレイスからサンドボックス化された
  プラグインをインストール：読み上げボイス、読書テーマ、辞書、本のように
  読めるフィード、新しいコマンド——そしてエージェントがすぐ使いこなす
  新しいツール。
- **言葉をあとのために。** 読みながら語彙に注釈をつけて、一度きりの検索では
  なく復習できる素材にします。
- **ページを自分のものに。** 言語、カラーテーマ、フォント、文字サイズ、行間
  などの読書設定を切り替えられます。
- **習慣が育つのが見える。** 読書時間の統計で、本やセッションをまたいだ進捗
  が見えます。
- **ほとんどの本を持ち込める。** EPUB、MOBI、AZW3、FB2、PDF、TXT、HTML、
  CBZ、CBR が形式変換なしで、共通の閲覧・選択・注釈・進捗モデルを共有します。

## なぜ違って感じられるのか

多くのアプリは AI をサイドバーにねじ止めします。ReadAware は逆から作られて
います。一つのエージェントが検索、コンテキストの組み立て、ツール使用、記憶
をオーケストレーションし、インターフェースはエージェントが操作できる表面
です。プラグインは同じ継ぎ目を外側から延長します——サンドボックス化され、
権限で守られ、ボイス、テーマ、辞書、フィード、コマンド、そしてエージェント
がすぐ使い方を知っているツールを追加できます。

この組み合わせこそが長期戦です。エージェントがアプリを操作する契約は、
プラグインが書かれる契約と同じもの——だからいずれ、エージェントがあなたの
代わりにアプリを拡張できるようになります。このリーダーは、自らを進化させる
ために設計されています。

その下にある工芸は、床であって売り文句ではありません。インターフェースは
変わらず静かで一貫し、ピクセル単位まで調整されています——タイポグラフィが
第一、コントロールは役立つときだけ、AI っぽさはなし。エージェントも読書
体験を乗っ取らず、そのそばに控えます。リーダーが注意を勝ち取るのはページで
あって、飾りではないからです。

デバイス間同期は計画中です。現在の ReadAware はローカルファースト：本、読書
進捗、注釈、会話、記憶はデバイスに残り、リモートのモデル推論はオプションで、
プロバイダーは自分で選べます。

## アーキテクチャ

ReadAware は 1 つのエージェントが検索、コンテキストの組み立て、ツール使用、
記憶の更新をオーケストレーションします。チャット履歴は記憶システムそのもの
ではなく素材であり、永続的なコンテキストは本をまたいだ読者の足跡から構築
されます。

```text
ReadAware アプリ
├── React インターフェース       本棚、リーダー、注釈、チャット、設定
├── ローカルエージェント         ツール、検索、コンテキスト、記憶更新
├── プラグインランタイム         サンドボックス worker、マーケットプレイス、コントリビューションポイント
├── SQLite                       プロダクトデータ、イベントログ、FTS、プロジェクション
└── ネイティブファイルシステム   取り込んだ本と大きな blob

リモートサービス
├── モデルプロバイダー           オプション。読者自身のアカウントで推論
└── 同期リレー                   計画中。暗号化されたイベントと blob の転送
```

信頼できる唯一の情報源はローカルにあります。生のドメインイベントが同期可能な
記録となり、記憶や検索の状態は再構築可能なプロジェクションです。検索には
ベクターデータベースではなく、SQLite FTS にスコープ・新しさ・重要度のシグナル
を組み合わせて使います。

プラグインとエージェントは同じドメイン API 層を通じてプロダクトに触れ、
すべての読み取り・書き込み・イベントには由来——ユーザー、プラグイン、
エージェント——が刻まれます。今日エージェントにできることは、明日プラグイン
が拡張できます。その逆もまた然り。

リポジトリ自体は Turborepo でオーケストレーションされた Bun workspace の
モノレポです。

| パス | 責務 |
| --- | --- |
| `apps/web` | React 19 インターフェース、TanStack Router、Jotai、Tailwind CSS v4 |
| `apps/desktop` | Tauri 2 シェルとネイティブなストレージ / プラットフォームコマンド |
| `apps/landing` | 公式サイトとリリースダウンロード |
| `packages/agent` | エージェントランタイム、モデルアダプター、検索と記憶のパイプライン |
| `packages/core` | ドメインエンティティ、イベント、ストレージ契約 |
| `packages/ui` | 共有デザインシステムと同居する Storybook ストーリー |
| `packages/plugin-types` | 公開プラグイン API サーフェス |
| `plugins/` | ファーストパーティプラグイン：辞書、テーマ、RSS、読み上げボイス |

アーキテクチャの決定と目標データ契約は
[`docs/agent-architecture.md`](docs/agent-architecture.md) と
[`docs/data-model.md`](docs/data-model.md) にあります。プラグイン API
リファレンスと公開ガイドは
[readaware.app/ja/docs/plugins](https://readaware.app/ja/docs/plugins) に
あります。
