# 本地数据与持久化

ReadAware 的结构化数据保存在桌面 SQLite，书籍和其他大文件放在本地文件系统。
业务修改通过事件与投影的共同提交保存，同步传递加密后的事件与文件。
文档整理于 2026-09-15；本页说明职责和入口，不维护第二份数据库建表脚本。

## 数据分成哪些类

| 类别 | 保存什么 | 恢复与同步规则 |
| --- | --- | --- |
| 事件日志 | 带身份和时钟的业务操作 | 作为重放与同步的基础，不能随意删除或改写历史 |
| 业务投影 | 书籍、批注、书签、阅读记录、记忆、画像、会话等可读状态 | 按事件语义更新；重建规则由投影实现负责 |
| 设备本地状态 | 设备身份、连接与同步进度、部分设置和界面状态 | 不因重建业务投影而被当作派生数据清空 |
| 文件与文件登记 | 书籍、封面、资源等文件，以及大小、哈希和可用状态 | 文件字节与数据库记录分别管理，需验证完整性与生命周期 |
| 本地索引与缓存 | FTS 等可重新生成的检索材料 | 可重建，不能成为独立业务事实源 |

不要从“存在于 SQLite”推导“全部能从事件恢复”或“全部应该跨设备复制”。聊天呈现
数据、本机配置、任务执行状态和凭据各有契约。历史遗留的未记事件数据也不能靠一次
重放凭空补回；完整恢复的保留规则见 [备份](../features/full-backup.md)。

## 写入、重建和故障

普通业务修改从领域命令进入 `commit_events`，事件追加和对应投影更新处于同一事务。
原生专用提交器也必须遵守其事件、投影及回执的事务契约；组件不能直接修改投影表。
例如聊天保存走 `ai_chat_commit`：会话事件与仅用于呈现的列（渲染片段、显示顺序、
本机错误占位）在同一事务写入，事件拥有的列只由应用事件的规则写。

重建与投影验证复用应用事件的规则，检查点支持从已知状态继续处理日志。设备本地
状态和非派生数据必须按各自规则保留。读取失败不能伪装成空列表，写入失败不能报告
保存成功；统一规则见 [错误处理](../../AGENTS.md#errors-and-ipc)。

凭据由原生密钥和密封存储路径处理，不进入普通事件、模型上下文或插件可读字段。
完整加密备份有专用凭据恢复机制，不能据此把密钥开放为普通数据库查询结果。

## 检索与上下文

默认检索使用 SQLite FTS 和结构化范围，不依赖 embedding 或向量数据库。书籍正文、
阅读位置、记忆来源与资源引用需要保留版本和授权边界，不能只凭一个旧 ID 猜当前状态。

- [画像、实体身份与自动整理](./identity-and-profile.md)：画像和人物身份的具体数据语义。
- [上下文包](./context-bundles.md)：有来源版本和披露边界的可导出阅读上下文。
- [同步](./sync-engine.md)：加密事件、文件和新设备引导。
- [完整备份](../features/full-backup.md)：归档、差异选择、合并与故障恢复。
