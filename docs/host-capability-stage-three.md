## OPS10 数据目录显示与 Reveal

代码入口：`maintenance 1.4 openSettings("data-location")` 与双 scope
`open_maintenance_settings`，宿主 `DataLocationGroup` / `nativeDataLocation`。

第三段必须检查：

- 从第二段覆盖 OPS10 的正式安装插件进入目录设置，确认显示的是隔离
  Tauri 数据目录，与该应用实际 SQLite/Blob 根目录相同，不是正式用户库。
- 插件和 Agent 返回值只有 `opened` 与 `surface`，不含目录、用户名、文件
  内容；定位时系统文件管理器不打开，必须由用户点击 Reveal。
- 点击 Reveal 后系统文件管理器确实显示对应目录；连续点击不重复派发
  同一在途 UI 操作。原生打开失败需捕获日志、稳定错误和本地化反馈。
- 目录查询故障不显示空目录或旧路径；瞬态错误重试恢复，权限错误不
  提供虚假重试。页面卸载、调用者退休/取消期间不交付迟到状态或定位。
- 在 packaged 轮次中通过正式插件安装重新验证该入口。截图/日志/IPC
  回执归入对应插件同一轮 evidence；macOS 的系统文件管理器行为不能
  外推为 Windows/Linux 已验。

目前证明仅为类型检查及针对性测试：调用了实际 Tauri JS API，但原生
IPC 为受控适配器，UI 是 JSDOM，未操作真实文件管理器。第二段尚未
指定正式插件流程，第三段结果与 evidence 路径仍为空，OPS10 保持
“接通（待 E2E）”。
