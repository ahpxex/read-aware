Plugin Architecture

能力只定义一次，按身份动态交付。

插件系统由 Domain Registry、Contribution Points 和 Host Services 组成。Settings 是 Domain；Appearance 只是 Settings 的一个 section。

目标架构已确定 2026-08-23。当前代码尚未完成迁移；本文不把“已经决定”写成“已经实现”。

一个模型，三类能力

三者共享同一种 registry 思想，但保留不同语义。不会收缩成一个松散的字符串调用接口。

01 / HOST STATE

Domain Registry

ReadAware 已经拥有的状态与行为。

  • 查询、命令与事件
  • 业务校验与持久化
  • 按 actor 裁剪权限
02 / PLUGIN SUPPLY

Contribution Points

插件提供的新实现、新选择或新动作。

  • 主题、字体与语音
  • 命令、工具与阅读模式
  • 注册、所有权与统一释放
03 / BOUNDED ACCESS

Host Services

必须由宿主代为执行的受限外部操作。

  • 网络、LLM 与 secrets
  • 文件选择、导出与剪贴板
  • 插件存储与定时任务

判断方法：宿主已有的是 Domain；插件新增的是 Contribution；需要宿主代办的是 Service。

目标 Domains

Domain 负责什么 插件初始开放
Library 书籍、源文件、元数据、目录与收藏 受限读取与明确命令
Reading 当前阅读会话、位置、导航、进度与时长 读取、导航、事件订阅
Annotations 高亮、笔记、书签与词汇引用 受限读取与明确修改
Conversations 书内及全局对话与消息元数据 窄范围、需知情同意
Settings 设置目录、解析值、作用域覆盖与变更事件 按具体 path 授予发现、读、写
Profile / Memory 用户画像、长期记忆与巩固状态 初期不对插件广泛开放

旧的 shelf 不保留兼容层：书库职责进入 Library，阅读会话职责进入 Reading。

Settings 就是 Domain

Appearance 不是独立 Domain。

它只是 Settings 的一个 section，与 Reading、AI、Sync、Plugins 等并列。

Settings 统一负责目录发现、取值、校验、作用域、提交、重置与变更订阅。UI、Agent 和 Plugin 走同一条提交路径。

当前使用哪个主题 Settings
插件提供一个新主题 Theme Contribution
当前使用哪个语音 Settings
插件提供语音引擎 Voice Contribution

插件只获得明确的 setting paths；secrets 始终由独立 Host Service 管理。

动态加载的准确含义

宿主不需要预先知道插件 ID。插件可发现被授权的 Domain，并注册到已有的 Contribution Point。

  1. 发现与校验 读取插件包，验证 manifest 与能力版本。
  2. 授权 按 plugin actor 解析权限与用户同意。
  3. 隔离启动 在 worker 中启动插件。
  4. 注入能力 Registry 生成裁剪后的 Domain、Contribution 与 Service 视图。
  5. 原子激活 全部注册成功后才进入 active；失败则完整释放。

动态不等于任意注入

新插件可以直接使用既有挂载点；一种全新的挂载点仍需宿主增加一次明确的 consumer， 因为宿主必须知道如何呈现、调用、授权和释放它。

  • 保留 worker sandbox
  • 保留宿主渲染的声明式 UI
  • 不开放 DOM、React、SQLite、Tauri 与任意文件系统
  • 更新采用候选版本、健康检查与自动回滚

迁移路线

现在没有第三方兼容负担，因此一次迁移所有第一方插件，完成后删除旧 API，不运行双轨系统。

Phase 1

冻结现有行为

盘点现有能力，并用行为测试保护真实工作流。

Phase 2

建立 Registry Runtime

从单一声明生成权限、actor view 与 worker API。

Phase 3

提升 Settings

让 UI、Agent、Plugin 共用目录、作用域与提交路径。

Phase 4

重建 Domains

拆分 Library 与 Reading，统一命令和事件。

Phase 5

统一 Contributions

统一注册、校验、所有权、发现与 disposal。

Phase 6

全量迁移与验证

迁移第一方插件，删除旧运行时，并在 Tauri 中验收。

什么时候算做完

  • 新增能力只修改一个权威定义，不再同步维护多份名单。
  • Settings 不再有旁路；Appearance 的特殊 API 被删除。
  • 插件不在宿主注册代码里按 ID 出现。
  • 所有 Contribution 都能被统一校验和完整释放。
  • 全部第一方插件只使用新运行时，旧 API 与兼容代码被删除。
  • 安装、启停、设置持久化、升级失败与回滚均通过 Tauri 桌面端验证。
