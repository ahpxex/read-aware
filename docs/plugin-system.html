Capability Architecture

插件能力，只有三种形状

读写产品状态走 Domain，扩展产品选择走 Contribution，需要宿主代办的外部操作走 Service。 插件动态加载，但权力边界由宿主定义。

架构参考：保留 2026-08-23 的三类划分；入口存在不证明完整语义、持久性、生命周期安全或桌面验收。

核对指引更新于 2026-09-09：统一目标与双端边界、实际接线矩阵、验收与 GAP01–GAP18。GAP 仍未关闭；本文对更新事务与旧结果隔离的概括不能视为所有失败路径已安全。

统一能力模型

Domain

ReadAware 已经拥有的状态和行为：查询、命令、事件、验证与持久化。

Contribution

插件提供的新动作、主题、语音、模式或内容实现；宿主负责消费和呈现。

Service

网络、模型、密钥、存储、计划任务等有边界的宿主能力，不是原生逃生口。

Domains

插件只看到权限允许的 actor view。所有写入都经过正式命令，并记录来源。

Library 1.5：批量删除双端接通，记录与文件结果分开

Agent 全局 delete_books 一次批准固定的 1–1000 个 ID；插件 removeMany 经 library:write 调用。记录/事件原子提交，文件失败仍明确报告记录已删。retryRemovalCleanup 只重试文件，不再写删除事件；任一书已恢复则整次拒绝文件清理。

Library Desk 0.1 实际组合选择、完整标题审阅、删除和清理重试；实时更新不清空搜索。macOS debug 已验两端回滚、拒绝/取消、恢复保护及菜单操作；不是自主模型、完整擦除或耐久恢复。大批量、打包和跨平台未验。完整契约 · 原生证据

Library 1.3：正文状态与请求控制双端接通

Agent get_book_text_status 与插件 getTextState 共享七种准备状态、三种文本存在性和源版本。查询不启动抽取或下载；全部节成功且最终索引落盘才就绪。短正文可以有字而没有索引章节，缺文件和失败不再误报无文字。

v5 断点只复用成功节，保留失败，区分最后一节读完与最终索引保存；旧记录惰性失效。Agent 和插件可请求准备、重建、观察及取消自己的任务；取消只释放自身租约，其他使用者继续工作，已派发读写不回滚。任务回执不代表完成，也不代表已取得抽取租约。

Text Desk 0.3 组合列表、状态、确认重建、请求详情与取消、明确开书；请求详情实时推送，列表仍显式刷新。插件任务限当前激活代，Agent 两 scope 共用进程所有者；每个所有者至多 16 活跃、64 保留请求，每任务 16 观察者，慢回调合并最新快照。

macOS 隔离 debug 已验权限 Worker、共享取消/退役、观察退订、重建冲突、真实 FB2、Agent 双 scope 与编译插件界面。暂停/优先级、耐久任务/超时、虚拟索引、全部格式、打包及跨平台仍缺；TXT05 仍为部分。完整契约 · 任务证据 · 正文事实证据

Library 1.4：Agent 与插件共享本书和跨书正文检索

1–12 个查询变体、每个至多 1024 字符，返回至多 100 个章内片段。指定书可以准备正文；跨书只读本地已持久索引，不触发批量抽取。缺书、非法参数和读取失败明确拒绝；结果不是可导航的 CFI/Range，也不是全书架穷尽或相关性排名。

Text Desk 0.4 组合搜索表单、精确/词元匹配列表、片段详情和明确开书。真实 macOS Worker 已验权限与错误，Agent 原有剧透围栏保留；跨书搜索后未准备的书仍未准备。分页、扫描预算、节内取消、打包及跨平台尚未完成。完整契约 · 原生证据

虚拟书删除：不再吞错，绑定清理等待持久化

事件提交失败时保留绑定并返回错误；绑定写入失败也不报成功。书已删后的重试可完成绑定清理，但 1.5 的删除通知先于文件释放：文件失败时绑定可能已清除，虚拟书重试不等于文件重试，需保留 ID 调用 retryRemovalCleanup。耐久恢复仍缺；这不是跨书籍、文件、绑定和 RSS 文档的原子事务。

真实 macOS Worker 命令与 Agent 插件工具已验证 SQLite 删除事件拒绝、绑定写拒绝和恢复重试；不是自主模型或完整 RSS 退订验收。并发创建删除、崩溃恢复、打包和跨平台仍缺，LIB13 保留部分。完整契约 · 原生证据

UI 1.2 / views 1.1：自有视图实时更新，关闭即退订

插件通过 live.subscribe 取得宿主签发的可见帧通道，再 publishView 完整画面。通道限当前激活代和视图；旧版本报 stale，外部或退休通道报 inactive。更新保留帧身份与现有草稿协调，不改变导航，不开放 DOM 或额外数据权限。

离开、嵌套弹窗或关闭立即撤通道，返回重新订阅当前值；迟到确认仍会释放。回调在画面提交后释放，中间快照不累积；失败保留旧画面并显示安全错误。每激活最多 16 通道；accepted 不是绘制完成，退订不是取消业务任务。

真实 macOS debug 已验回调、草稿、逆序、跨插件、嵌套与退出；Text Desk 从阅读菜单打开后，无需刷新便由 Running 0/3 到 Completed 3/3。动态贡献状态见下一项；宿主 Agent 统一可用性、全表单/焦点/大数据、打包和跨平台仍缺，MORE05 保留部分。完整契约 · 验证证据

版本与权限

每个 Domain、Contribution、Service 和声明式 UI schema 独立版本化。插件清单声明能力 semver 范围，也用整数 schemaVersion 管理自己的 KV 与文档数据。

权限控制“能不能做”

Domain 读写、网络、LLM、剪贴板、全局主题等需要语义化授权；Settings 使用精确路径。

版本控制“能不能正确做”

未知能力、无效范围、未获授权的依赖或不兼容版本都会阻止激活。

安全更新

独立暂存候选版本不会覆盖当前插件。
只读候选activate 只能读取和声明；挂载点先暂存，写数据、密钥、网络和业务命令都被阻止。
停写与快照先暂停并排空上一版，再取 KV、文档和 schema 快照；随后提交文件，刷新候选镜像并执行 storage-only 迁移。
显式提升健康与迁移都成功后，候选贡献才一次性进入全局 Registry。
按阶段恢复只有文件提交后才回滚文件、迁移可能写入后才恢复数据；健康检查失败不覆盖仍在运行的旧实例。恢复前停止并排空候选。
持久确认Worker 写与 schemaVersion 等待落盘；旧失败不抹掉新写，远端 origin 随持久写传递。跨界并发和真实桌面升级故障仍待验收，不宣称所有资源已安全释放。

始终不开放

插件运行在 Worker 中，界面由宿主声明式渲染。
